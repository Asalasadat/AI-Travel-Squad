# دلني — واجهة المستخدم (Frontend)

واجهة الويب لمنصة **دلني**: منصة توصيات سياحية لفلسطين. يحدد المستخدم مدنه ونوع رحلته وفئته العمرية وعدد الأشخاص وميزانيته، فتعرض الواجهة أنسب الأماكن مرتبة حسب الملاءمة، مع خريطة ومقارنة وحفظ ومشاركة.

> هذا الملف يخص مجلد `Frontend` فقط. للباك إند ونموذج الذكاء الاصطناعي، راجع مجلدي `Backend` و`AI&ML`.

## المميزات

- نموذج تفضيلات من خمس خطوات مع ملخص فوري بجانبه.
- نتائج مرتبة حسب الملاءمة مع مؤشر نسبة ملاءمة لكل مكان.
- فلاتر حسب نوع المكان، و«ضمن ميزانيتي»، و«دخول مجاني»، وترتيب بالملاءمة أو الأقل تكلفة.
- خريطة تفاعلية للأماكن، تفرّق بين الموقع الدقيق والتقريبي.
- مقارنة بين مكانين جنباً إلى جنب.
- حفظ الأماكن المفضلة ونسخ القائمة.
- مشاركة الرحلة برابط ورمز QR، ومشاركة عبر تطبيقات الجهاز.
- صفحة تفاصيل لكل مكان فيها حاسبة تكلفة وخريطة مصغّرة.
- واجهة عربية بالكامل (RTL) وتتكيّف مع الجوال.
- نصوص المستخدم بصيغة محايدة (اختر، تأكد).

## التقنيات

لا توجد خطوة بناء. الصفحات HTML ثابتة تحمّل المكتبات من CDN:

| المكتبة | الاستخدام |
| --- | --- |
| Tailwind CSS (CDN) | التنسيق، مع ألوان وأنصاف أقطار معرّفة بمتغيرات CSS |
| Lucide | الأيقونات |

## التشغيل المحلي

**المتطلبات**

- تشغيل الباك إند على `http://localhost:5286` (من مجلد `Backend/AiTravelSquad.Api`: `dotnet run --launch-profile http`).
- خادم محلي للملفات الثابتة، مثل إضافة **Live Server** في VS Code.
- اتصال بالإنترنت لتحميل المكتبات والخطوط والخرائط.

**الخطوات**

1. شغّل الباك إند وتأكد أن `http://localhost:5286/swagger` يفتح.
2. افتح مجلد `Frontend` في VS Code وشغّل `index.html` بـ Live Server (يعمل عادة على المنفذ 5500).
3. لا تفتح الملفات مباشرة من المتصفح (`file://`)، فسياسة CORS بالباك إند تسمح بعناوين `localhost` و`127.0.0.1` على منافذ محددة فقط، منها 5500 و5501 و3000.

## الصفحات وتدفق الاستخدام

```
index.html → preferences.html → results.html → place.html
                     ↑                |
                     └── تعديل التفضيلات
```

### `index.html` — الرئيسية

قسم البداية (Hero)، ثم «ثلاث خطوات»، ثم «أشهر الوجهات»، ثم دعوة للبدء. بطاقات الوجهات تُبنى بالسكربت من `GET /api/Places/{id}`:

- المصفوفة `FEATURED` داخل السكربت تحدد رقم كل مكان واسمه الإنجليزي.
- قبل عرض البطاقة تتحقق الصفحة أن الاسم الإنجليزي القادم من الباك يطابق المتوقع. لو تغيّر رقم المكان في قاعدة البيانات لا تظهر بطاقة خاطئة، ويظهر تحذير في الكونسول.
- إذا لم يرجع الباك المكان تختفي بطاقته بدل أن تنكسر الصفحة.

### `preferences.html` — التفضيلات

| السؤال | النوع | ملاحظات |
| --- | --- | --- |
| المدن | متعدد الاختيار | مطلوب اختيار مدينة على الأقل |
| نوع الرحلة | متعدد الاختيار | النوع «عائلية» مخفي (انظر `HIDDEN_TRIP_TYPES`) |
| الفئة العمرية | اختيار واحد | إجباري، ولا توجد قيمة افتراضية |
| عدد الأشخاص | عدّاد من 1 إلى 50 | الأشخاص فوق 10 سنوات فقط |
| الميزانية | رقم بالشيكل | ميزانية المجموعة كلها، مع أزرار سريعة 100 و300 و500 و1000 |

- ملخص الرحلة يتحدّث لحظياً بجانب النموذج.
- عند الإرسال تُحفظ التفضيلات في `sessionStorage`، ثم يُفتح `results.html?s=<payload>`. صفحة النتائج هي التي ترسل الطلب للـ API وتعرض التحميل والأخطاء.
- يمكن فتح الصفحة بمدينة محددة: `preferences.html?city=Nablus` (روابط الفوتر تستعمل هذا).

### `results.html` — النتائج

1. تقرأ الرابط `?s=` وتفكّ تفضيلات الرحلة، أو تستعملها من `sessionStorage`.
2. ترسل `POST /api/Recommendations` (مهلة 90 ثانية، لأن أول طلب قد يتأخر بسبب خدمة الـ AI).
3. تجلب تفاصيل كل مكان عبر `GET /api/Places/{id}` (الإحداثيات، التكلفة، مستوى الميزانية، الاسم والوصف بالعربي، الصورة).
4. ترسم الصفحة **مرة واحدة** بعد اكتمال كل شيء، فلا تتغير البطاقات بعد ظهورها.

المحتوى: بطاقة لكل مكان (رقم الترتيب، حلقة النسبة، النوع، المدينة، الوصف، التكلفة، «مطابق لـ»)، فلاتر وترتيب، خريطة، مقارنة، تبويب «المحفوظة»، ومشاركة.

عند فشل الطلب تظهر رسالة حسب الحالة:

| الحالة | الرسالة |
| --- | --- |
| 404 | لا توجد أماكن مناسبة للميزانية والتفضيلات |
| 502 | خدمة التوصيات غير متاحة حالياً |
| 400 | مشكلة في البيانات المُدخلة |
| انتهاء المهلة | خدمة التوصيات تأخرت بالرد |
| غير ذلك | تعذر الاتصال بالخادم |

### `place.html` — تفاصيل مكان

يُفتح بـ `place.html?id=<رقم المكان>`. يعرض صورة أو أيقونة النوع، أزرار الحفظ والمشاركة والاتجاهات، وصفاً، وجدول معلومات، وسبب الترشيح، وخريطة مصغّرة، وحاسبة تكلفة (التكلفة للشخص × العدد مقابل الميزانية). إذا جاء المستخدم من نتائج بحث يظهر ترتيب المكان ونسبة ملاءمته وقائمة «من نتائجك أيضاً».

## شريط التنقل والفوتر

الملف `assets/layout.js` يبني الشريط والفوتر ويحقنهما في كل صفحة، ويُضمَّن قبل نهاية `<body>`. نمط الشريط يُحدَّد بالسمة `data-nav` على وسم `body`:

| القيمة | الاستخدام | الروابط |
| --- | --- | --- |
| `overlay` | الرئيسية (شفاف فوق صورة الهيرو) | كيف يعمل، وجهات مختارة، المحفوظة، وزر «خطط رحلتك» |
| `solid` | باقي الصفحات (ثابت بخلفية فاتحة) | الرئيسية، خطط رحلتك، توصياتي، المحفوظة |

- «توصياتي» تظهر فقط لو وُجدت نتائج في الجلسة.
- الصفحة الحالية تُسطَّر (`aria-current="page"`). صفحة المكان تُحسب تحت «توصياتي»، و`results.html?tab=saved` تُحسب تحت «المحفوظة».
- عداد «المحفوظة» يتحدّث تلقائياً.
- القائمة الكاملة تظهر من عرض 1024px، وتحته يظهر زر القائمة المنسدلة.
- `data-footer="off"` يخفي الفوتر.
- روابط أقسام الرئيسية (كيف يعمل، وجهات مختارة) موجودة في الفوتر لباقي الصفحات.

**واجهة `window.Dalni`** (تُستعمل من الصفحات):

| العنصر | الوظيفة |
| --- | --- |
| `LS_FAV` | مفتاح المفضلة في `localStorage` |
| `refreshFavBadge()` | تحديث عدّاد المحفوظة |
| `HIDDEN_TRIP_TYPES` | أنواع رحلات مخفية من الاختيار (حالياً `["Family"]`) |
| `normName(s)` | توحيد الأسماء للمطابقة |
| `imageIndex()` | فهرس صور احتياطي من `assets/places.json` |

## التواصل مع الـ API

العنوان الأساسي `API_BASE = "http://localhost:5286"` معرّف في ثلاثة أماكن: `index.html` و`results.html` و`place.html`.

### `POST /api/Recommendations`

الجسم (يبعثه `results.html`):

```json
{
  "Cities": ["Nablus"],
  "TripTypes": ["Cultural"],
  "AgeGroup": "Family",
  "Budget": 500,
  "GroupSize": 4
}
```

- `AgeGroup` نص واحد: `All` أو `Family` أو `Youth`. الباك إند يترجمها للعربية (الجميع، عائلة، شباب) قبل إرسالها لخدمة الـ AI.
- `Budget` هي ميزانية المجموعة كلها بالشيكل.

الحقول التي تقرأها الواجهة من كل عنصر في `recommendations` (بأي حالة أحرف):

| الحقل | الاستخدام |
| --- | --- |
| `placeId` | رقم المكان. القيمة 0 تعني أنه لم يُطابَق بقاعدة البيانات، فلا تظهر روابط التفاصيل والحفظ |
| `placeName`, `placeType`, `city`, `description` | الاسم والنوع والمدينة والوصف |
| `matchScore` | الملاءمة. قيمة بين 0 و1 تتحول لنسبة مئوية |
| `rankOrder` | الترتيب |
| `imageUrl` | الصورة (اختياري) |

### `GET /api/Places/{id}`

الحقول المقروءة: `placeName`, `placeNameAr`, `descriptionAr`, `city`, `placeType`, `latitude`, `longitude`, `estimatedCostIls`, `budgetLevel`, `tripType`, `ageGroup`, `imageUrl`. عند الرد 404 تعرض صفحة المكان رسالة «ما لقينا هالمكان».

## التخزين في المتصفح

| المفتاح | المكان | المحتوى |
| --- | --- | --- |
| `aiTravelPrefs` | `sessionStorage` | تفضيلات آخر بحث |
| `aiTravelResults` | `sessionStorage` | آخر رد من الـ API |
| `dalni:items` | `sessionStorage` | نسخة خفيفة من النتائج (بالأسماء العربية) لصفحة المكان |
| `dalni:favorites` | `localStorage` | الأماكن المحفوظة (`id, name, city, type`) |

**رابط المشاركة**: `results.html?s=<payload>`، والـ payload هو JSON للتفضيلات مشفّر Base64 آمن للروابط. الصفحة تتحقق منه وتنظّفه (`sanitizePayload`) وتعيد الطلب من الباك.

## الصور

تُختار صورة المكان بهذا الترتيب:

1. `imageUrl` في عنصر التوصية.
2. `imageUrl` في تفاصيل المكان (`GET /api/Places/{id}`).
3. ملف `assets/places.json` الاختياري: مصفوفة عناصر بالشكل `{ "name": "<الاسم الإنجليزي>", "image": "<رابط>", "imageCredit": "<المصدر>" }`.
4. إذا لم توجد صورة أو فشل تحميلها: خلفية متدرجة مع أيقونة حسب نوع المكان.

- تُرسل الصور بدون معلومات المصدر (`referrerpolicy="no-referrer"`) لأن بعض المواقع تمنع عرض صورها من مواقع أخرى.
- الصورة التي يفشل تحميلها تُحذف بصمت، فتظهر الأيقونة.
- الروابط المقبولة تبدأ بـ `https://` أو `http://` أو `assets/` فقط.

## الخريطة والمواقع

- أغلب أماكن قاعدة البيانات لها إحداثيات **احتياطية** بمركز المدينة (نقطة واحدة مشتركة لكل مدينة)، وليست موقعاً فعلياً.
- الموقع يُعتبر **دقيقاً** فقط إذا كان على بعد أقل من 15 كم من مدينته ولا يساوي نقطة المدينة الاحتياطية.
- المكان الدقيق يظهر بدبوس مرقّم. غير الدقيق يُجمَّع في دائرة منقطة عند مركز مدينته مع عدد أماكنها، وتظهر عليه عبارة «موقع تقريبي».
- الثوابت `CITY_XY` (مراكز المدن) و`CITY_FALLBACK` (النقاط الاحتياطية) موجودة في `results.html` و`place.html`.

## الإعداد والنشر

1. غيّر `API_BASE` في الملفات الثلاثة إلى رابط الباك المنشور.
2. أضف رابط الواجهة المنشورة إلى قائمة CORS بالباك إند (`Program.cs`)، وإلا يحجب المتصفح الطلبات.
3. Tailwind بالـ CDN مناسب للتطوير فقط، وقبل النشر يُفضَّل بناء ملف CSS بواسطة Tailwind CLI.
4. روابط المشاركة تحتوي عنوان الصفحة الحالي. على `localhost` تعمل على جهاز صاحبها فقط، وتظهر بالنافذة رسالة تنبيه بهذا.

وتأكد أن الباك إند وخدمة الـ AI يقبلان القيمة الجديدة.

## ملاحظات وقيود معروفة

- **خدمة الـ AI على Render**: أول طلب بعد فترة خمول قد يتأخر أو يفشل (502). الواجهة تنتظر حتى 90 ثانية.
- **أرقام الأماكن المميزة في الرئيسية** مرتبطة بقاعدة البيانات. لو أُعيد إنشاؤها من ملف مختلف قد تتغير الأرقام، وحينها تُخفى البطاقة (بسبب فحص الاسم) حتى تُحدَّث المصفوفة `FEATURED`.
- **الأماكن المحفوظة** تُخزَّن برقم قاعدة البيانات، فتتأثر عند إعادة إنشائها.
- **روابط الصور**: بعض روابط فيسبوك مؤقتة وتنتهي صلاحيتها، وروابط مصغّرات جوجل غير مضمونة. الأفضل استضافة الصور بمكان ثابت.
- **الفئة العمرية** سؤال إجباري، وتأثيرها على الترتيب يعتمد على ما تدعمه خدمة الـ AI.
- لا توجد اختبارات آلية بعد.

## قواعد المساهمة

- رسائل الـ commit **بالإنجليزية** وبصيغة [Conventional Commits](https://www.conventionalcommits.org): `type(scope): summary`.
- الأنواع الشائعة: `feat` ميزة جديدة، `fix` إصلاح، `refactor` إعادة هيكلة بلا تغيير سلوك، `docs` توثيق، `style` تنسيق، `chore` أعمال جانبية.
- النطاق لهذا المجلد: `frontend`. أمثلة:
  - `feat(frontend): add results page with filters, map, compare and saved places`
  - `fix(frontend): repair shared layout script and replace removed brand icons`
  - `docs(frontend): add Arabic README with setup, pages and API contract`
- الشيفرة بدون تعليقات، والشرح موجود في هذا الملف.
- نصوص واجهة المستخدم بصيغة محايدة (اختر، تأكد) وباللهجة المستعملة في باقي الصفحات.
- عند أي تعديل على شكل الطلب أو الرد بين الفرونت والباك، حدّث قسم «التواصل مع الـ API» هنا.
